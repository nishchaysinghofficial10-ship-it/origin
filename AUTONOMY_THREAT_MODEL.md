# ORIGIN — Autonomy Threat Model

Scope: the bounded-autonomy layer added in v1.5 (`origin/autonomy.py`,
`origin/scheduler.py`). System threats are in `THREAT_MODEL.md`; the LLM and
web-evidence surfaces have their own documents.

## Trust boundary

```text
operator (trusted)
  → limits, --allow-network, --allow-provider, approved URLs ... validated
  → ORIGIN core (trusted code)
      → autonomy policy .......... chooses among ALREADY-PERMITTED actions
      → work items ............... schema-validated DATA, never code
      → dispatch ................. existing engine; every gate still applies
      → external actions ......... only with per-run operator permission
```

Autonomy adds a *chooser*, not a new capability. It cannot construct an action
type, widen a limit, or reach anything the engine would not already permit.

## Adversaries and attacks

| # | Adversary | Attack | Control | Evidence |
|---|---|---|---|---|
| N1 | Anyone with write access to the mission | Craft a work item that runs a shell command or arbitrary code | `validate_item()` rejects unknown action types, and `run_experiment` items may not carry `design`, `command`, `code`, `runner` or `argv`. Experiment code is generated by the domain and re-validated by the sandbox | `test_invalid_work_items_are_rejected`, `test_autonomy_cannot_bypass_experiment_validation` |
| N2 | Same | Queue a `retrieve_source` item pointing at `file://`, `http://`, or a private address | Schema requires `https://`; the retrieval layer then re-applies the full URL/address/host/robots policy at execution | `test_autonomy_cannot_bypass_url_policy` |
| N3 | Same | Hand-edit `autonomy/state.json` to raise a priority, clear an attempt count, or inject an action | Items are re-validated on load; anything invalid is **quarantined** as FAILED and surfaced by `origin verify` rather than executed | `test_item_failing_validation_on_load_is_quarantined` |
| N4 | Two operators / a cron overlap | Two processes mutate one mission concurrently | Atomic `O_CREAT|O_EXCL` mission lease with owner/pid/host; a second process is refused with an explanatory error | `test_second_scheduler_cannot_acquire_the_lease` |
| N5 | Same | Steal a lease that "looks stale" | Never automatic. A stale and a live lease are indistinguishable from outside; release requires `recover-lock --force` and is audited in two logs | `test_a_stale_lease_is_never_stolen_automatically`, `test_manual_recovery_requires_force_and_is_audited` |
| N6 | Crash / power loss | An action is claimed, then the process dies; a naive scheduler re-runs it and double-charges | The claim is checkpointed **before** execution; on recovery the item becomes `interrupted` with "completion is UNKNOWN", is never auto-re-run, and waits for the operator | `test_crash_after_claim_is_recovered_conservatively` |
| N7 | Duplicate scheduler tick (cron overlap, retried invocation) | The same action runs twice | Idempotency keys collapse equivalent items; completed items are never selectable again; budgets are charged by the engine, not the queue | `test_duplicate_tick_does_not_duplicate_work_or_budget`, `test_idempotency_key_collapses_duplicate_items` |
| N8 | Flaky dependency | Retry storm / hot loop burning budget | Typed retry classification, capped exponential backoff with a persisted `not_before`, per-item attempt cap, consecutive-failure cap, idle-tick cap. A deferred item is invisible to the policy until its wake time | `test_retryable_failure_backs_off_then_fails_terminally`, `test_consecutive_failure_cap_stops_the_run`, `test_idle_ticks_do_not_busy_loop` |
| N9 | Same | A *safety refusal* gets retried until it succeeds by luck | Policy violations, schema failures, unsafe designs, disallowed URLs, robots refusals and cancellations are classified non-retryable; unknown classes are non-retryable by default | `test_non_retryable_failures_are_never_retried` |
| N10 | Untrusted external content (web page, LLM output) | Influences which action autonomy takes, or becomes a finding | Content never enters the queue: work items are seeded from **mission state** (phase, hypothesis statuses, contradiction counts), not from document or model text. Retrieved claims stay `SPECULATION`; `Evidence` is only ever created by an experiment | `test_web_claims_never_become_evidence_under_autonomy` |
| N11 | Operator confusion | An "autonomous" run silently touches the network or spends provider credit | Both are opt-in per run, refused by the policy otherwise, and marked `<NETWORK>` / `<PROVIDER>` in `autonomy plan` *before* execution. The run banner prints the external authority in force | `test_autonomy_does_not_use_network_or_provider_without_permission`, `test_a_live_brain_is_not_called_without_permission` |
| N12 | Corrupted mission | Autonomy acts on inconsistent research state | Every tick runs `state.verify()` first and stops with `unsafe_or_invalid_state` if it finds a blocking problem | `test_unsafe_state_stops_the_scheduler` |
| N13 | Anyone | Secrets leak into autonomy artifacts | No credential is ever read by the autonomy layer; state and decision logs are asserted free of `sk-ant-`, `api_key=` and absolute paths | `test_autonomy_state_is_portable_and_secret_free` |
| N14 | Runaway process | A background daemon keeps running unsupervised | There is no daemon. `run()` is a bounded foreground loop; when it returns, nothing of ORIGIN is executing | `test_step_limit_stops_the_scheduler`, `test_wall_clock_limit_stops_the_scheduler` |

## Residual risks

1. **No exactly-once guarantee for external actions.** If a process dies
   between an external side effect and its checkpoint, ORIGIN records the
   ambiguity and stops. It does not — and cannot, at this layer — guarantee the
   action happened exactly once.
2. **The lease is advisory and filesystem-local.** It protects against two
   processes on one filesystem. It does not work across a network filesystem
   with unreliable `O_EXCL`, and it does not protect a mission copied elsewhere.
3. **A quarantined work item is inert but the tampering is not attributed.**
   `verify` reports *that* an item was malformed, not who changed it. Autonomy
   state is not signed or tamper-evident.
4. **Seeding is heuristic.** It reads mission state and proposes plausible next
   actions; it does not prove that the chosen action is the *most valuable* one,
   only that it is permitted, affordable and deterministic.
5. **Backoff has no jitter.** Deterministic timing is better for testing and
   inspection, but many missions started together would retry in lockstep.
6. **Wall-clock limits are checked between ticks**, so a single long action can
   overrun the limit; it cannot be interrupted mid-experiment without losing the
   sandbox's own timeout guarantees.
